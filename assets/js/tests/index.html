Místní testy FAIR průvodce

English · Testy v katalogu

Každý test má vlastní identifikátor, popis a odkaz na otázku, kterou může předvyplnit. Popis v katalogu uvádí, co test hledá a co z nalezeného podkladu nelze dovodit. Testy nenahrazují původní požadavky citovaných standardů.

PID a metadata digitálního objektu

Testy přijímají podklady, které kontrola již načetla: výsledek rozlišení PID a reprezentace metadat přiřazené tomuto objektu. Čtou podporovaná pole DataCite a Schema.org i výslovné deklarace profilů. Samy nic nestahují.

Každá reprezentace se posuzuje samostatně. Neúplná pole z různých záznamů se neskládají do úplné odpovědi. Nerozpoznaný slovník, odlišný objekt, chybějící pole nebo nedostupný záznam nevedou k záporné odpovědi. Není-li dost podkladů, otázka zůstane otevřená.

Testy CDIF a FDO sledují jen jednotlivé doložitelné prvky. Rozlišený PID, běžná metadata ani deklarace profilu samy neprokazují shodu s celým standardem. Vzorek záznamů neprokazuje vlastnosti celého repozitáře.

Implementace: object.js. Sdílené čtení polí a registr funkcí: assess.js.

Veřejný softwarový repozitář

Testy přijímají veřejná metadata repozitáře a vybrané textové soubory k jednomu úplnému identifikátoru commitu. Bez rozlišeného commitu se nevytváří žádné předvyplnění.

Podporují vybraná pole CodeMeta, autory v nejvyšší úrovni CITATION.cff, závislosti v package.json, requirements*.txt a pyproject.toml, neprázdný licenční soubor a vybrané zápisy definic testů. CodeMeta musí označovat právě posuzovaný repozitář. Identifikátor článku v preferred-citation se nepovažuje za identifikátor softwaru.

Nalezená deklarace je obvykle jen částečný podklad. Kontrola neinstaluje závislosti, nespouští cizí kód ani testy a neověřuje archivaci, funkčnost nebo správnost licencí. Nečtené či zkrácené soubory nepodporují odpověď.

Implementace: software.js. Sdílené čtení polí a registr funkcí: assess.js.

Identita a volání

Identifikátor má tvar guide-cdif-01 nebo guide-software-14. Funkce FairGuide.selfcheck.localTests["guide-cdif-01"](observations) vybere podklady pro danou otázku a připojí identitu testu. Volání assessObject(check, result, sample) a assessSoftware(check, repository) nejprve vyhodnotí načtené podklady a poté zavolají jednotlivé registrované funkce.

V API je každý test popsaný v api/tests/<identifikátor>.json. Záznam obsahuje vazbu na otázku, popis, funkci, implementaci a dokumentaci. Přílohy jsou součástí RO-Crate průvodce. Seznam testů v API vyžaduje otevření průvodce přes HTTP.

Local tests in the FAIR guide

Tests in the catalogue

Each test has its own identifier, description and link to the question it can prefill. Its catalogue description explains the observed condition and the limits of the evidence. These tests do not replace the original requirements of the cited standards.

PID and digital-object metadata

Tests consume evidence already retrieved by the check: PID-resolution results and metadata representations matched to the object. They read supported DataCite and Schema.org fields and explicit profile declarations. They make no requests themselves.

Each representation is assessed separately. Incomplete fields from different records are never combined into a complete answer. Unknown vocabularies, a different object, missing fields and unavailable records never produce negative answers. A question remains open when evidence is insufficient.

CDIF and FDO tests cover individual observable elements. A resolved PID, ordinary metadata or a profile declaration alone does not establish conformance to the whole standard. A sample does not establish repository-wide properties.

Implementation: object.js. Shared field readers and function registry: assess.js.

Public software repository

Tests consume public repository metadata and selected text files at one full commit identifier. No prefill is produced without a resolved commit.

Supported evidence includes selected CodeMeta fields, top-level CITATION.cff authors, dependencies in package.json, requirements*.txt and pyproject.toml, a non-empty licence file and selected test-definition syntax. CodeMeta must identify the repository being assessed. An article identifier in preferred-citation is not treated as a software identifier.

A declaration usually provides only partial evidence. The check never installs dependencies, runs inspected code or tests, or verifies preservation, functionality or licence validity. Unread or truncated files do not support answers.

Implementation: software.js. Shared field readers and function registry: assess.js.

Identity and invocation

Identifiers follow the form guide-cdif-01 or guide-software-14. The function FairGuide.selfcheck.localTests["guide-cdif-01"](observations) selects evidence for that question and adds the test identity. Calls to assessObject(check, result, sample) and assessSoftware(check, repository) first evaluate retrieved evidence and then call the registered functions.

Each test has a record at api/tests/<identifier>.json, linking its question, description, function, implementation and documentation. Attachments belong to the guide's RO-Crate. The API test list requires opening the guide over HTTP.
